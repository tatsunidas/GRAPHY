### Issue 1 — [NPEリスク] DcmQRSCP#configureRemoteConnections() の `||` 演算子誤用

**重要度:** Critical  
**ファイル:** `src/main/java/com/vis/dicom/dimse/DcmQRSCP.java:895`

#### 概要
`configureRemoteConnections()` 内で、サーバー設定の `ciphers` フィールドの nullチェックに `||`（OR）を使っているため、`ciphers` が `null` のとき **必ず NullPointerException が発生** します。

DIMSEのリモート接続設定時にクラッシュし、GRAPHYのDICOM通信機能（C-STORE/C-MOVE受信）が停止します。

#### 問題のあるコード
```java
// DcmQRSCP.java:892-900
String aet = (String) entry.get("aetitle");
Connection remote = new Connection();
remote.setHostname((String)entry.get("hostname"));
remote.setPort((int)entry.get("port"));
// ★バグ: ciphers が null のとき || の右辺が評価され NPE
if(entry.get("ciphers") != null || !entry.get("ciphers").equals("")) {
    remote.setTlsCipherSuites(((String)entry.get("ciphers")).split(":"));
}
```

`entry.get("ciphers") != null` が `false` のとき、`||` 演算子により右辺の
`entry.get("ciphers").equals("")` が評価されます。`ciphers` は `null` なので
`.equals("")` の呼び出しで `NullPointerException` が発生します。

#### 修正提案
```java
// || を && に変更し、ローカル変数で二重評価も排除
String ciphers = (String) entry.get("ciphers");
if (ciphers != null && !ciphers.isEmpty()) {
    remote.setTlsCipherSuites(ciphers.split(":"));
}
main.addRemoteConnection(aet, remote);
```

#### 期待される効果
- `ciphers` が null または空文字のサーバー設定でも GRAPHY が正常に起動できる
- TLS暗号スイート未設定のサーバーへの接続が安全にスキップされる

### Issue 2 — [NPEリスク] SeriesConditionExtractorDialog 抽出処理での StudyUID/SeriesUID null チェック漏れ

**重要度:** High  
**ファイル:** `src/main/java/com/vis/core/search/SeriesConditionExtractorDialog.java:700-702`

#### 概要
抽出処理の `doInBackground()` 内で DICOM ヘッダから StudyInstanceUID / SeriesInstanceUID を取得した後、null チェックを行わずに `getSeriesFiles()` へ渡しています。
`getSeriesFiles()` は内部で `DatabaseHandler#getFileLocationsSeriesLevel()` を呼び出しますが、このメソッドは `studyUid` または `seriesUid` が `null` の場合に明示的に `NullPointerException` をスローします（DatabaseHandler.java:1314）。

特定ベンダーのDICOMファイルではタグが欠損することがあり、抽出処理が途中で例外終了します。

#### 問題のあるコード
```java
// SeriesConditionExtractorDialog.java:700-702
String studyUid = header.getString(0x0020000D);   // null が返る可能性あり
String seriesUid = header.getString(0x0020000E);  // null が返る可能性あり
List<File> filesToCopy = getSeriesFiles(isTreeTable, studyUid, seriesUid, repFile);
// ↓ 内部で DatabaseHandler.getFileLocationsSeriesLevel(studyUid, seriesUid) が呼ばれる

// DatabaseHandler.java:1314 (呼ばれる先)
if (studyUid == null || seriesUid == null) {
    throw new NullPointerException("DB:getFileLocationsSeriesLevel:: studyUid or seriesUid must be non-null.");
}
```

#### 修正提案
```java
// SeriesConditionExtractorDialog.java:700-702 付近
String studyUid = header.getString(0x0020000D);
String seriesUid = header.getString(0x0020000E);

if (studyUid == null || seriesUid == null) {
    String msg = "Skipped (missing StudyUID or SeriesUID): " + repFile.getAbsolutePath();
    Log.logger.warning("SeriesConditionExtractorDialog: " + msg);
    publish(msg);
    publish(i + 1);
    continue;
}
List<File> filesToCopy = getSeriesFiles(isTreeTable, studyUid, seriesUid, repFile);
```

#### 期待される効果
- StudyInstanceUID / SeriesInstanceUID が欠損した非標準DICOMファイルでも抽出処理が中断されない
- スキップされたファイルがUIとログに明示される

### Issue 3 — [重複コード] SwingWorker#process() の型分岐ロジックが executeVerification と executeExtraction で重複

**重要度:** Medium  
**ファイル:** `src/main/java/com/vis/core/search/SeriesConditionExtractorDialog.java:586-594, 779-786`

#### 概要
`executeVerification()` と `executeExtraction()` それぞれで生成する `SwingWorker` の `process(List<Object> chunks)` メソッドに、全く同一の型分岐ロジック（`Object` を `Integer` / `String` に振り分けてプログレスバーとテキストエリアを更新するコード）が重複しています。DRY原則（Don't Repeat Yourself）の違反です。

#### 問題のあるコード
```java
// executeVerification() 内 SwingWorker (SeriesConditionExtractorDialog.java:586-594)
protected void process(List<Object> chunks) {
    for (Object o : chunks) {
        if (o instanceof Integer) {
            progressBar.setValue((Integer) o);
        } else if (o instanceof String) {
            txtVerificationResult.append((String) o + "\n");
        }
    }
}

// executeExtraction() 内 SwingWorker (SeriesConditionExtractorDialog.java:779-786) -- 全く同一
protected void process(List<Object> chunks) {
    for (Object o : chunks) {
        if (o instanceof Integer) {
            progressBar.setValue((Integer) o);
        } else if (o instanceof String) {
            txtVerificationResult.append((String) o + "\n");
        }
    }
}
```

#### リファクタリング提案
```java
// SeriesConditionExtractorDialog にプライベートメソッドを抽出
private void applyProgressChunks(List<Object> chunks) {
    for (Object o : chunks) {
        if (o instanceof Integer) {
            progressBar.setValue((Integer) o);
        } else if (o instanceof String) {
            txtVerificationResult.append((String) o + "\n");
        }
    }
}

// executeVerification() 内 SwingWorker
@Override
protected void process(List<Object> chunks) {
    applyProgressChunks(chunks);
}

// executeExtraction() 内 SwingWorker
@Override
protected void process(List<Object> chunks) {
    applyProgressChunks(chunks);
}
```

#### 期待される効果
- 同一ロジックが1箇所に集約され、プログレスバー更新ロジックの変更が1箇所で済む
- テストコードを書く場合のカバレッジ向上
